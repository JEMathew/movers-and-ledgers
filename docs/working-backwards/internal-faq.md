# Internal FAQ

Strategy hypotheses and operating trade-offs, 17 October 2026. This document does not claim measured demand, economics or production performance.

**Why GenAI?** Ambiguous evidence needs explanation, uncertainty and trade-offs that rigid labels alone may not communicate well. Gemini earns a place only if grounded explanations improve informed human decisions. Deterministic rules remain preferable for schema, compatibility, state, money, authorization and reconciliation. Evaluate reasoning independently from financial correctness.

**Why agents instead of conventional workflows?** The current parent orchestrators are deterministic Python components with bounded specialist responsibilities. Logical agent labels clarify context, evidence, tool and escalation contracts. They do not prove autonomous LLM delegation. Keep conventional code where it supplies reliable, testable control. Introduce an actual model runtime only for a measured reasoning need.

**Why a Reviewer?** The accountant needs challenge, not a longer restatement. The initial review contract independently checks allowed mapping evidence for unsupported treatment, contradictions and missing information, and recommends a next action. Separate golden cases must distinguish it from the advisor. The reviewer has no financial or approval authority. A deterministic Reviewer must be labeled accurately.

**Why a separate Judge?** The Agent Quality Judge evaluates output quality, grounding, tool/policy compliance and recovery offline. The Product Quality Judge evaluates the implemented experience, promise delivery and submission readiness. Neither belongs in the customer's approval/execution path. The Reviewer serves a customer decision. The two Judges serve internal evaluation.

**Why gamification?** A short office mission can make abstract migration concepts tangible for a newcomer. This is a learning hypothesis, not demonstrated conversion impact. Build one meaningful evidence puzzle with accessible controls, evaluate transfer into Explore Demo, and stop if it distracts or trivializes financial decisions.

**What is the competitive wedge?** A provider-neutral continuity from learning and readiness to human decisions, deterministic verification and first productive use. No claim of market uniqueness, provider compatibility or superiority is substantiated by this package. Benchmark actual supported tasks and trust controls before comparative marketing.

**What makes the approach scalable?** A canonical model separates source adapters, transformations and target adapters. Versioned policy and evidence contracts reduce provider leakage. Owner-scoped persistence and explicit operational budgets bound resource use. Current snapshot storage and synthetic fixtures do not establish production throughput or multi-tenant scale. New provider pairs need semantic tests and operating-cost evidence.

**What happens when Gemini fails?** Enforce timeout/call/output bounds, validate evidence references, retain the full durable reservation conservatively, including on timeout/failure, and annotate sanitized operational completion without refunds and return a sanitized safe fallback. Preserve the deterministic proposal and human workflow. Do not fabricate a model response or silently substitute an unlabelled answer. Operational kill switch must stop new model calls.

**How do we prevent financial harm?** Synthetic scope, authenticated ownership, current-version decisions, allowlisted tools, approved manifests, idempotency, checksummed checkpoints, bounded recovery and deterministic reconciliation. Model advice, Reviewer and Judges cannot mutate financial state. Sensitive configuration and productive invoice approval remain human. Production use requires additional independent review.

**Why Cloud SQL and Firestore?** Cloud SQL/PostgreSQL is the chosen financial/transactional authority because lifecycle, decisions, target state and receipts need atomic consistency. Firestore is reserved for operational activity, kill switch, owner usage and global budget reservations. It must not duplicate financial authority or contain raw financial payloads. Existing audit/session records remain separate until an actual integration exists. Last-known Firestore API was disabled. Source code or a diagram alone does not prove activation.

**How should future accounting-provider adapters work?** Separate read-only source discovery from scoped target writes. Publish supported entities, history/tax/configuration boundaries, transformations, omissions and rollback behavior per pair. Preserve lineage and provider identifiers. Contract-test rate limits, retries, idempotency and accounting semantics. Obtain reviewed credentials, permissions and real-data authorization before any connection.

**What are the operating costs?** No measured cloud cost or commercial price is established. A cost model must include Cloud Run CPU/memory/request time, SQL instance/storage/backups, Gemini input/output tokens, Firestore reads/writes/reservations, Storage/egress, logging and human support. Model-call count alone excludes important costs. Use owner quotas, global durable budget reservations and an operational kill switch; verify billable prices/region and instrument actual usage before publishing an estimate.

**What would invalidate the strategy?** Accountants may prefer existing provider tools and manual handover; Play may fail to teach; review may add friction without improving decisions; data semantics may make adapters uneconomic; safe handling/support costs may exceed willingness to pay; users may distrust explanations even when correct. Test these hypotheses with representative tasks, independent accounting review and observed outcomes. Stop expansion when the evidence contradicts the customer value.

**What blocks submission now?** Integration acceptance, actual cloud capability evidence, the official deck template/portal checks and a final authentic 3–4 minute video must be verified. Draft documents, scripts and historical footage are preparation, not evidence of those completed deliverables.
