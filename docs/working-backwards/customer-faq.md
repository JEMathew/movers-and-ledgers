# Customer FAQ

This FAQ distinguishes intended customer value from the current bounded synthetic Beta. It is not a promise of real provider support.

**Why migrate?** A business may need a different accounting environment because the current system no longer supports its work. MoveBooks helps examine compatibility and risk before deciding. Whether a move is appropriate remains a business/accounting decision.

**Who is MoveBooks for?** Accountants, bookkeepers, small-business owners and finance operators. The current Beta uses synthetic accounting environments and owner-scoped decisions. Future specialists, approvers and administrators require explicit supported roles.

**How does Play help?** The opening mission lets an accountant explore a small office, collect evidence and solve a readiness/mapping problem. The learning goal is comprehension and confidence. Game success does not approve a financial operation or prove migration readiness. New mission functionality requires candidate acceptance.

**What is Explore Demo?** A guided Harbor Light Books synthetic journey through Understand, Prepare, Move, Verify and Start. It demonstrates discovery, readiness, planning, mapping, human decisions, safe execution, reconciliation, configuration and a synthetic first invoice.

**What does Try Your Data support?** The documented controlled-package-v1 CSV/JSON files, individually or a supported flat ZIP, using only permitted synthetic or de-identified test data. The parser validates bounds, schema, types, relationships and accounting balance. It explains issues and allows replacement/revalidation. A browser-local fallback keeps the preview on the device and must label any unavailable hosted handoff. Hosted uploads remain separately release-gated. Never submit confidential customer data.

**What does Gemini do?** On your request, the shared bounded advisor explains an existing proposal in Planning, Mapping, Resolution, Configuration or Onboarding. It may cite permitted evidence, identify uncertainty and recommend review. It does not approve, edit financial records, run migration, retry operations, reconcile accounts or declare FPU. Availability is separate from deterministic workflow availability. Failure returns a safe fallback.

**What does the independent Reviewer do?** The intended initial slice challenges the ambiguous account mapping using allowed evidence and a separate review contract. It returns outcome, concerns, contradictions, uncertainty and your next action. Implementation and deployment status must be visible. It cannot approve or change the mapping.

**What decisions remain mine?** You review the plan, ambiguous or consequential mappings, remediation and sensitive configuration. You approve the productive invoice before execution. The system checks your identity, ownership, current version and applicable policy. Advice cannot stand in for your decision.

**How is financial correctness established?** Deterministic controls verify counts, references, balances, checksums and the agreed productive task. A model explanation is not reconciliation evidence. A mismatch blocks progression until a permitted correction and revalidation resolve it.

**How is privacy protected?** The Beta prohibits confidential source data. Model projections contain only allowlisted synthetic context. Owner access and server validation protect supported workflows. Browser-local preview must not transmit records. Hosted collection requires independent isolation, malware, retention/deletion and abuse gates. No production privacy or compliance certification is claimed.

**What does successful migration mean?** The agreed scope, required data/configuration, access/onboarding and exception controls pass, then an authorized user completes the first agreed productive task and the system verifies its evidence. In the Beta this is an explicitly approved synthetic invoice. An import count, game unlock or AI statement alone does not establish success.

**What happens if something fails?** The product shows the blocker and next step, preserves known-good evidence and uses idempotency/checkpoints for permitted recovery. Transient failures may retry within policy. Consequential or uncertain cases require human action. No real provider write is performed in this Beta.
